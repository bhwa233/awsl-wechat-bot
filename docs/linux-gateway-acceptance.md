# Linux Gateway 实机验收

日期：2026-10-22。环境：Debian 13 x86_64、Linux WeChat 4.1.13.9、X11、AT-SPI、PulseAudio。所有发送仅在授权测试群完成，逐条发送且不自动重试；以 Chatlog 自消息及 server ID 确认送达。

窗口管理接口已走通正常流程：主窗口与独立窗口 state、窗口列表、调试树、聊天选择、上下滚动、独立窗口开关、状态查询、重复开窗、缓存读写与恢复。失效 path 被拒绝。

生产 Gateway 的 WebSocket 已验证非法正则返回 error 后继续有效订阅、取消订阅、断开重连，以及 `send_message` 入队后的真实送达。不存在的提及名称在两类窗口中验证了草稿清理与原文回退，没有为此发送额外消息。

## 故障与修复

- **同名会话误切换**：禁止操作 Chatlog 或当前列表中存在歧义的名字；仅在目标列表项已选中且输入框、聊天标题都匹配时跳过点击。同名场景以模拟数据验证拒绝行为，没有创建或重命名真实群聊。
- **同 seq 消息填满一页**：批量接口增加可选 `offset`，默认 0；按 seq/local_id 稳定排序，跨库合并后分页。Linux 遇到完整边界页继续拉下一页，保留去重。多页、迟到边界消息、跨库分页以构造数据回归验证，没有修改微信库制造碰撞；真实 Chatlog HTTP 分页也已核对。
- **开独立窗后主窗口空白**：实机复现微信将聊天移到独立窗后，主窗口聊天区和输入框同时消失；重新选择会话即恢复。Console 开窗及重复开窗后自动重新选择该会话，已验证两个窗口并存时主窗口保持可用。整体 `available` 只表示可访问窗口，不能代替聊天区和输入框的就绪状态。
- **最大化主窗口引用失败**：AT-SPI 返回的消息行覆盖整个聊天区宽度，行中央可能位于气泡外。现在仅在已核对的消息行内寻找菜单，复制正文并精确核对，再选择引用并确认预览；正文、位置或焦点变化则停止。不在没有菜单时按 Escape，防止微信将主窗口隐藏到托盘。
- **非法 WebSocket 正则断连**：共用协议校验将正则编译错误转成验证错误，返回 error，连接仍能继续接受有效订阅。

## 后续四项修复

- **TTS 操作锁**：Linux 与 Windows Console 一样，在 TTS 合成前取得 Console 锁，期间切换聊天会返回忙；全局 UI 锁仍仅在操作微信时取得。实机适配器在受控慢合成期间拒绝切换，合成失败后可继续操作。
- **部分数据库失败**：v2 batch 严格读取全部数据库时间索引，并在任一相关库查询失败时整批报错；Gateway 保留游标重试。构造的跨库故障及 HTTP 失败回归确认不会提交部分进度，恢复后可读到较旧消息；未对在线微信库制造故障。
- **取消录音失败**：在真实主窗口、独立窗口录音期间注入取消按钮失败，确认持久化标记保留、默认输入及微信录音流仍处于临时无声设备；新适配器读取标记后拒绝 UI 操作。恢复取消后，验证录音流关闭、默认麦克风恢复、设备和标记清理、操作可继续。暂停标记位于 `~/.cache/awsl-wechat-gateway/pending-recording.json`，不能通过直接删标记恢复操作。
- **缓存恢复结果**：对实机适配器注入含无效条目的缓存，部分失败和全部失败均返回 `available=false` 及正确计数；正常缓存恢复返回成功。测试未覆盖或修改用户保存的正常缓存文件。

上述无发送测试在至少 120 秒后再次读取 Chatlog，确认没有新增自消息。相关记录为 `linux-four-fixes-20261022-r1.json`。
随后复测主窗口 TTS 和独立窗口 MP3，均由 Chatlog 确认，下载解码与源音频包络相关系数分别超过 0.97；临时设备及暂停标记已清理。发送记录为 `linux-four-fixes-send-20261022.json`。本轮回归共 63 项通过。

## 临时附件异常清理修复

图片/文件发送创建临时文件后，用 `finally` 在返回失败或抛出异常时安排清理，包含录音保护拒绝操作及 UI 锁获取失败；成功发送继续使用原有清理计划。新增 3 项回归覆盖录音保护异常、发送返回失败及成功路径，Gateway 共 56 项通过。

Linux 机器额外验证主窗口与独立窗口参数下的图片/文件共 4 种组合：使用私有测试录音标记并注入停止确认失败，确认没有执行 UI 操作，真实后台清理线程删除附件及文件临时目录，同时保留测试录音标记。测试仅将清理等待缩短为 0.05 秒，没有开启真实录音或发送消息。记录为 `linux-attachment-cleanup-20261022.json`。

## 2026-10-23（Asia/Singapore）三项修复与 Console 状态补齐

- **麦克风恢复**：正常发送和异常恢复均先完成默认输入恢复与设备卸载，成功后才移除恢复标记；清理异常不吞掉。回归覆盖清理失败保留标记、重试恢复及正常路径只清理一次。实机主窗口注入恢复默认输入失败，独立窗口注入设备卸载失败，均验证标记保留和后续恢复；最终独立窗口单次卸载失败后自动恢复的语音也已由 Chatlog 确认。
- **长文件名与创建失败**：文件名限制为 200 个 UTF-8 字节，给微信本地缓存追加重名后缀留余量；截断时保留普通扩展名并增加原文件名的短哈希，避免不同长文件名被截成同名。创建/部分写入失败同步清理文件与目录。100/300 个汉字、长 ASCII、同前缀不同尾部及模拟磁盘写入失败均有回归；实机两种窗口发送 300 个汉字的原文件名，均确认消息、下载和内容 SHA256 一致。
- **窗口缓存**：任一窗口缺少可验证会话 ID 时拒绝保存，已有缓存保持原字节不变；读取时拒绝空白、缺失和非字符串 ID。实机适配器使用私有测试缓存及无法匹配的窗口注入验证，没有修改用户原缓存。
- **Console 状态**：消息返回 `content/quote/raw_text`，解析中文引用格式和 Linux 英文 `Quote …'s message`；主/独立窗口均读取了同一条真实引用，并核对 Chatlog type 57 原消息 ID。AT-SPI 未暴露 Qt 消息类名，时间行结合格式和相对行高识别；实际发送 `12:35` 并确认两种窗口仍将它识别为正文。会话列表同时解析置顶、免打扰、多行预览及时间。中文格式和其他时间样式使用构造数据回归，实机界面为英文。
- **调试能力**：`include_patterns=true` 返回实际 AT-SPI 接口、属性、动作及文本能力；两种窗口均通过 HTTP 验证，false 时不附加详情。只调用只读方法，不执行动作，不调用 `Properties.GetAll`，也不伪造 Windows UIA Pattern 或类名。

本轮 Gateway 69 项、Chatlog 3 项、Cortex 4 项、服务监督器 3 项，共 79 项 Python 回归通过；前端浏览器 34 项检查通过，改动的 Linux 代码和新增测试通过 Ruff，`uv lock --check` 与 `git diff --check` 通过。

## 验证边界

收消息链路使用真实 Chatlog 群消息，在隔离的 Gateway 实例中回放并经过适配器、Detector、队列和 WebSocket；已核对正文、sender、sender_name、at_users、自消息过滤和重复读取去重。这验证实际读取与广播链路，不代表另一个成员主动配合发送新消息的实时延迟测试。隔离实例没有 Cortex 或 Webhook 客户端。

本机未配置 LocalAI，TTS 验收使用 EdgeTTS；LocalAI 提供方未实测。超长音频由真实解码器拒绝；未通过实际发送超过上限的语音来验证。独立窗口接口不提供引用；纯 Wayland 不支持。ARM64、其他微信版本、其他语言界面及 Windows/macOS 未做本轮实机验收。
发送验收覆盖主窗口与独立窗口并存状态下的两个入口；完全关闭所有独立窗口、或隐藏主窗口后，各自重新运行全部发送类型尚未完成。

机器上的完整记录保存在运行用户的 `~/.awsl-wechat-bot/test-results/`：`linux-full-20261022.json`、`linux-full-guards-20261022.json`、`linux-receive-full-20261022.json`、`linux-ws-live-20261022.json`。记录含案例状态、server ID、媒体核验及保护分支的确认结果；本地文档不保存密钥或 token。
